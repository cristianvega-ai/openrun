# Completion generator audit — round 4

This inventory covers every generator allowed at review 3 (253 ordinary and 21 isolated). The policy now permits 39 environment-reviewed and 14 additionally isolated generators (all 53 require a network-isolated local context) and denies 421. Alias generators are listed separately below and require the same local context. A deny decision is not evidence that a tool is malicious: it means no adequate real-tool proof is available.

Evidence boundaries: the installed executable and shell are trusted; project configuration, filenames, interpreter selection and typed tokens are not. Network isolation denies direct network operations, not all possible delegation through local services. Tested versions do not establish safety for every future release or configuration.

The app tests named below run real tools through `LocalCommandExecutor`. Missing tools and required historical Git versions exit 86, which fails nextest; the CI skip allow-list remains empty. The final validation record is maintained in CHANGES.md.

## Project-selected runtime sweep

All generators that actually invoke pip, Poetry, PDM, conda, pyenv/asdf/mise, npm/yarn/pnpm/bun, Bundler/Rake, Gradle/Maven wrappers, make, cargo/rustc, Go or direnv are denied. This also conservatively denies their file-reading generators unless they are one of the separately tested single Git reads. uv tool listing and rustup docs path are the two tested exceptions described above. The uv interpreter and cargo path-toolchain attacks have real-tool regressions; the npm 6 `.npmrc` onload hook and Bazel filename injection also have controls in `project_code_tests`. A missing generator for a named tool does not add any execution permission.
